# SOTERIA ROOM

YouTube 재생목록을 중심으로 검색기, 월드컵, 블로그, 커뮤니티를 골라 쓰는 로컬 웹 보관실입니다. 참고 명세의 MVP 단계나 PostgreSQL 선택을 강제하지 않고, 사용자의 실제 요청과 기존 월드컵 프로젝트를 기준으로 만들었습니다.

## 켜기

Windows에서 **`SOTERIA-ROOM.cmd`를 더블 클릭**하세요. 실행 창을 열어둔 상태에서 브라우저로 **http://localhost:5173/** 에 접속합니다. 처음에는 필요한 패키지를 설치하므로 조금 걸릴 수 있습니다. Node.js 22.13 이상이 필요합니다.

직접 실행하려면:

```powershell
node scripts/local-start.mjs
```

실행 창에서 Ctrl+C를 누르면 종료합니다. 이미 실행 중이라면 새로 실행하지 말고 주소로 접속하세요. 재생목록 파일을 매달 수정할 필요는 없습니다.

## 재생목록 갱신

앱 화면을 열 때 마지막 성공으로부터 하루가 지났으면 채널의 공개 재생목록을 **다음 페이지까지 전부 발견**하고, 오래된 저장분과 새 목록을 순차 갱신합니다. 화면을 계속 열어두면 매시간 갱신 필요 여부를 확인합니다. PC나 브라우저가 꺼져 있는 동안은 동작하지 않습니다.

`가져오기 · 동기화 → 지금 전체 동기화`는 캐시를 건너뛰어 다시 읽습니다. 외부 채널·일부 공개 목록은 URL로 직접 추가할 수 있습니다. 수동 추가한 외부 목록은 자동 채널 갱신 대상이 아니며 같은 URL을 넣어 갱신합니다.

- 재생목록 ID 기준으로 갱신하므로 중복 등록하지 않습니다.
- 검색 결과는 영상 ID 기준으로 중복을 합치고 모든 소속 목록을 표시합니다.
- 목록별 저장은 전체 페이지 수집이 성공한 뒤 실행합니다. 실패하면 이전 저장 내용을 유지하고 실패 목록을 표시합니다.
- 0곡·1곡 목록도 보관할 수 있습니다. 월드컵에는 최소 2곡이 필요합니다.
- 채널에서 사라진 목록은 자동 삭제하지 않습니다. 비공개·삭제·중복 영상 때문에 실제 표시 개수와 YouTube의 전체 항목 수가 다를 수 있습니다.
- 기존 2,048곡 수집 제한을 제거했습니다. 비정상적인 반복·500페이지 초과·요청 실패는 오류로 처리하며 일부 수집 결과로 덮어쓰지 않습니다.
- YouTube 공개 페이지 구조가 바뀌거나 요청이 제한되면 가져오기가 실패할 수 있습니다. 기존 수집기의 공식 API 대체 경로도 남겼습니다. 서버의 `YOUTUBE_API_KEY` 설정은 선택 사항이며 실제 키는 소스에 넣지 마세요. 키 없는 공개 페이지 경로를 실제 데이터로 검증했습니다.

월별 분류는 `2026.09`, `9월의 픽(2026)` 같은 제목에서 읽습니다. 여러 달 범위나 날짜 없는 목록은 ‘그 밖의 재생목록’으로 남깁니다. 곡 검색은 제목·채널·소속 재생목록을 대상으로 하며 화면에는 200곡까지 표시하고 전체 결과의 링크를 복사할 수 있습니다.

## 블로그와 커뮤니티

네이버 RSS에 제공되는 최근 글과 각 갤러리 첫 페이지의 최근 글을 읽습니다. 오래된 고정 공지는 제외합니다. 전체 과거 글을 저장하는 크롤러는 아닙니다. 외부 원문은 텍스트만 표시하며 클릭하면 원문으로 이동합니다. 원문 사이트가 차단하거나 형식이 바뀌면 오류와 직접 방문 링크가 표시됩니다. 글 목록은 서버 메모리에 5분 캐시됩니다.

## 기존 코드와 수정 위치

재사용 내역과 원본 버전은 **REUSE.md**에 기록했습니다.

| 수정할 부분 | 파일 |

## 데이터와 나중의 PC 운영

기존 프로젝트의 D1 호환 SQLite 로컬 저장소를 사용합니다. 별도 데이터베이스 서버 설치 없이 `.wrangler/state/`에 보관됩니다. 재생목록과 월드컵 결과를 백업하려면 앱을 종료하고 이 폴더를 복사하세요. 좋아요와 마지막 갱신 시간은 사용한 브라우저의 로컬 저장소에 있습니다. `.wrangler/state`는 Git 업로드 대상이 아닙니다.

현재 실행기는 이 PC의 `127.0.0.1`에만 연결됩니다. 다른 사람에게 공개하는 서버 설정은 하지 않았습니다. 상시 PC 운영 시 브라우저와 분리된 예약 수집, 관리자 인증, 백업 및 접근 설정을 추가하면 됩니다. 원본 프로젝트의 Sites 설정은 보존했지만, 이 작업에서 원격 사이트·GitHub에는 배포하거나 업로드하지 않았습니다.

## 검증

```powershell
node --experimental-strip-types --test tests/tournament.test.ts tests/archive.test.ts tests/discovery.test.ts
node node_modules/typescript/bin/tsc --noEmit
node scripts/run-framework.mjs build
# 로컬 서버가 켜져 있고 재생목록이 저장된 상태에서 실행
node tests/local-integration.mjs
```

새 로컬 통합 검사는 실제 저장 목록, 입력 검증, 대진, 소유권, 결과 위조 방지, 중복 저장 방지, 세 외부 글 목록을 확인하며 자신이 생성한 테스트 게임만 정리합니다. 원본 `tests/integration.mjs`는 그대로 보존했지만 신규 검사는 `tests/local-integration.mjs`를 사용하세요.

## 컬렉션 · 표지 · 랜덤 디깅

- 홈에는 큐레이션만 표시합니다. `202X.XX`, `a bundle of songs`, `Before 2021`은 월별·연간 수집 보관함으로 이동했습니다. 수집과 월의 픽을 분리하고 연도·월로 좁힐 수 있습니다.
- My Recap 22개와 Kawaii Voice Playlist 10개는 전용 탭입니다. 채널 홈에 묶인 실제 시리즈 ID와 읽기 쉬운 제목은 `lib/series.json`에서 수정합니다. 리캡은 일반 채널 재생목록 탭에 안 나오는 공유 목록이므로 자동 동기화 대상에 함께 포함합니다.
- 제목·기간·곡 수·조회수·갱신일을 오름차순/내림차순으로 정렬합니다. 조회수가 제공되지 않으면 `미제공`으로 표시하고 항상 뒤에 둡니다. 조회수 정렬에서는 연도별로 묶지 않아 전체 순서가 유지됩니다.
- 커스텀 표지는 YouTube의 재생목록 microformat에서 읽습니다. 제공되지 않을 때만 첫 영상으로 대체합니다. 표지와 공개 조회수는 동기화할 때 갱신됩니다. 수집 코드는 `lib/youtube-metadata.ts`, 저장은 `playlist_meta` 테이블입니다.
- 검색과 랜덤 곡 뽑기는 전체/픽/큐레이션/수집/각 시리즈 범위를 제공합니다. 같은 영상 ID는 한 번만 후보에 들어갑니다. 곡은 1~100개, 채널은 1~30개를 중복 없이 뽑습니다.
- 랜덤 디깅 → 구독 채널 뽑기에서 연결된 Google Sheets를 다시 가져오거나 새 CSV로 교체합니다. CSV의 채널 URL과 제목을 사용하고 빈 행·중복 URL·따옴표를 처리합니다. 실패한 파일은 기존 목록을 덮어쓰지 않습니다. 반년이 지나면 갱신 안내가 표시되며 자동으로 원본 시트를 수정하지 않습니다.
- 제공된 시트에는 구독자 수가 없으므로 구독자 수 기준의 하꼬 필터는 적용하지 않습니다. 저장된 구독 채널 전체에서 무작위로 발견하는 방식입니다.
- `components/random-discovery.tsx`는 랜덤 화면, `lib/collections.ts`는 분류·정렬·무작위 선택, `lib/subscriptions.ts`는 CSV 파서, `app/api/subscriptions/route.ts`는 로컬 구독목록 저장입니다. 구독 목록도 `.wrangler/state/` 백업에 포함됩니다.

2026-09-26 확인: 재생목록 121개, 중복 제외 영상 45,131개, 구독 채널 3,923개. 비공개·삭제 영상 및 원본 변경에 따라 다음 동기화 시 수치는 달라질 수 있습니다.
